## 环境里踩到的坑（记下来，别人大概率也会遇到）

1. **git clone 报 `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`**
   Windows 的 schannel TLS 后端在这台机器上起不来。解法：改用 OpenSSL 后端
   ```powershell
   git -c http.sslBackend=openssl clone <url>
   # 或在仓库里固定：git config http.sslBackend openssl
   ```
   注意代理 `127.0.0.1:7897` 本身是好的，CONNECT 能建立，问题只在 TLS 后端。

2. **`git submodule update --init` 失败**
   报 `sh.exe: *** fatal error - couldn't create signal pipe, Win32 error 5`。是 shell 被限制创建管道，不是仓库问题。手工替代：
   ```powershell
   git clone https://github.com/Reactive-Network/reactive-lib-omni.git starter/lib/reactive-lib-omni
   git -C starter/lib/reactive-lib-omni checkout 3ade0dcf1d27e67e5783ef807e73a1b9e0c0cce8
   ```

3. **`forge build` 报 `Error: 拒绝访问 (os error 5)`**
   forge 要写 `~/.svm` 的 solc 缓存，被这个会话的沙箱挡了。**自己的终端里不会遇到**，直接 `forge build` 就行。

4. **`禁止运行脚本`，.ps1 跑不起来**
   默认执行策略是 Restricted。临时绕过：
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\faucet-lreact.ps1 -Address 0x...
   ```
   或一次性改掉：`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

5. **官方文档的 faucet 地址在链上是空的**（2026-11-17 实测）
   Sepolia 的 `0x9b9BB25f…f434` 在 4 个 RPC 上都是 0 字节代码、余额 0、nonce 0 —— 空账户，发进去就是丢币。
   Base Sepolia 的 `0x2afa…5967` 是活的（1534 字节代码、8.2 ETH 余额）。
   对照组能正常读出代码（Sepolia Callback Proxy 218 字节、USDC 1793 字节），排除工具问题。
   已在 `faucet-lreact.ps1` 加了 `cast code` 自检，地址没代码直接中止。
